# Железо и CS2 — тир-лист для универсальности

Справочник для адаптивной логики Source2Boost: детектнутое железо → **тир** → профиль/советы.
Сверху вниз (от старших к младшим). CS2 запускается почти на всём, что проходит минимум, поэтому
здесь важны не отдельные модели, а **семейства/поколения** и их тир.

## Минимальные требования CS2 (Valve)

| | Минимум | Рекомендуется |
|---|---|---|
| ОС | Windows 10 64-bit | Windows 10/11 64-bit |
| CPU | 4 аппаратных потока (Intel Core i5-750 и выше) | 6+ ядер, высокий single-thread |
| RAM | 8 ГБ | 16 ГБ, двухканал |
| GPU | DirectX 11, Shader Model 5.0, ≥1 ГБ (напр. GeForce 610 / GT 1030 / HD 7000) | RTX 2070 / RX 5700 и выше |
| Диск | 85 ГБ (лучше SSD) | NVMe SSD |

## Как CS2 нагружает железо (важно для тиров)

- **CPU — главный лимит.** Движок Source 2 упирается в **single-thread + объём L3-кэша**. Поэтому
  чипы с 3D V-Cache (AMD X3D) непропорционально сильны в CS2, а старые многоядерники без кэша слабы.
- **RAM — второй лимит.** Двухканал и частота/тайминги заметно влияют на 1% low (игра
  memory-latency-чувствительна).
- **GPU — вторичен** на competitive-low (наши настройки графики). На минималках почти любая
  дискретка тянет 300+ FPS, лимит переносится на CPU.

## Легенда тиров

| Тир | Что это | Что делает приложение |
|---|---|---|
| **S** | Топ, CS2 400–800 FPS | Профиль Safe/Optimal хватает; агрессивные твики не нужны, упор на латентность |
| **A** | Высокий, 300–500 FPS | Optimal; всё ровно |
| **B** | Средний, 200–350 FPS | Optimal/Maximum; выжимаем 1% low |
| **C** | Бюджет/старый (CPU-bound), 120–250 FPS | Maximum + все анти-стуттер твики; **основная ЦА** |
| **D** | Минимум, 60–150 FPS | Maximum + графика на макс. FPS + честно предупреждаем о потолке железа |

# Оперативная память

CS2 очень чувствителен к **латентности памяти** и **двухканалу**. Одноканал = −20–40% в 1% low.

| Тип (год) | JEDEC (базовые) | XMP/EXPO разгон | Платформы | Заметка для CS2 |
|---|---|---|---|---|
| **DDR5** (2021+) | 4800, 5600 | 6000, 6400, 7200, 8000+ | AM5, LGA1700/1851 | Сладкая точка **6000 CL30** (AMD) / 6400–7200 (Intel) |
| **DDR4** (2014+) | 2133, 2400, 2666, 2933, 3200 | 3600, 4000, 4266+ | AM4, LGA1151/1200/1700 | Сладкая точка **3200–3600 CL16** |
| **DDR3** (2007+) | 1066, 1333, 1600 | 1866, 2133, 2400 | LGA1150/1151(часть), AM3+ | Топ для старых: **2133–2400** ← целевой ПК (DDR3-1866) |
| DDR2/DDR1 | 533–1066 / 266–400 | — | старьё | Ниже минимума CS2 |

**Правила приложения по памяти (уже частично есть в BottleneckAnalyzer):**
- 1 планка → предупредить про одноканал (поставить вторую = крупнейший прирост).
- Разнокалиберный набор → работает на скорости медленной планки, XMP нестабилен.
- Частота ≈ базовой JEDEC при ≥2 планках → вероятно **XMP/DOCP выключен** → совет включить.
- <8 ГБ → предупредить (CS2 минимум), фикс. pagefile.

# План: как это ложится в универсальность

Следующий шаг (код) — превратить эти таблицы в классификатор:

1. `HardwareInfo` уже детектит модель CPU/GPU (WMI) и частоту/каналы RAM.
2. Добавить `HardwareTier { S, A, B, C, D }` + `CpuTier(model)`, `GpuTier(model)`, `RamTier(...)`:
   парсим семейство/поколение из строки модели (как уже парсим Intel-поколение в старом `IsOldCpu`),
   мапим в тир по таблицам выше. Неизвестное → эвристика по потокам/частоте/памяти (fallback).
3. Тир → **адаптивный профиль по умолчанию** и формулировки диагноза («потолок железа честно»):
   - S/A → рекомендуем Safe/Optimal, упор на латентность;
   - B → Optimal;
   - C/D → Maximum + графика max-FPS + мягкое предупреждение о физическом потолке.
4. Прогноз FPS (`FpsEstimator`) откалибровать по тиру, а не только по эвристике потоков.

Источники требований: [CS2 System Requirements](https://community.skin.club/en/articles/cs2-system-requirements),
[PCGameBenchmark](https://www.pcgamebenchmark.com/counter-strike-2-system-requirements).
Актуальность поколений 2025–2026 (RTX 50 / RX 9000 / Ryzen 9000 / Core Ultra 200S) сверена по TechPowerUp.
